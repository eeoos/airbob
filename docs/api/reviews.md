# 리뷰 작성·조회·이미지

리뷰 목록 조회는 로그인 없이 가능하다. 작성·수정·삭제와 이미지 변경은 로그인한 작성자 기준으로 처리하며 회원 ID를 직접 보내지 않는다.

## 작성 자격과 호출 순서

1. `POST /api/v1/accommodations/{accommodationId}/reviews`로 본문과 평점을 보낸다.
2. 201 응답의 `data.id`를 리뷰 ID로 보관한다.
3. 사진이 있으면 `POST /api/v1/reviews/{reviewId}/images`로 추가한다.

```json
{"rating":5,"content":"숙소가 깨끗하고 교통이 편리했어요."}
```

```json
{"success":true,"data":{"id":201}}
```

작성할 때 다음 조건을 다시 확인한다.

- 회원이 ACTIVE이고 숙소가 PUBLISHED여야 한다.
- 해당 숙소에 본인의 CONFIRMED 또는 CANCELLATION_FAILED 예약이 있어야 한다.
- 예약의 체크아웃 시각에 도달했거나 지나야 한다. 숙소 현지 날짜만으로 판단하지 않는다.
- 해당 숙소에 본인의 PUBLISHED 리뷰가 없어야 한다. DELETE·HIDDEN 리뷰는 중복 검사에서 제외하므로 삭제 후에는 다시 작성할 수 있다.

예약별 리뷰가 아니라 **회원·숙소별 게시된 리뷰**를 검사하므로 `reservation_uid`는 입력하지 않는다. 같은 회원의 동시 작성 요청도 순서대로 검사한다. 이미 게시된 리뷰가 있으면 409/V004이며, 응답을 받지 못한 뒤 재시도해서 이 코드를 받았다면 목록에서 작성 결과를 확인한다.

`rating`은 필수 정수이며 1~5다. `content`는 필수이며 빈 문자열·공백만 있는 문자열은 허용하지 않는다. 최대 길이는 1024자이며 Java 문자열 길이를 기준으로 하므로 이모지 등 일부 문자는 2자로 계산한다. 입력 오류는 400/C001, 본문 Content-Type 오류는 415/C011이다.

## 목록과 정렬

`GET /api/v1/accommodations/{accommodationId}/reviews?sortType=LATEST&size=20`

게시된 리뷰만 조회하며 삭제·숨김 리뷰는 제외한다. 숙소의 현재 상태나 존재 여부를 별도로 검사하지 않으므로 미게시 숙소의 기존 게시 리뷰도 반환될 수 있다. 결과가 없으면 404가 아닌 200과 `reviews=[]`다.

| sortType | 정렬 |
|---|---|
| LATEST | 작성 시각 내림차순, ID 내림차순. 기본값 |
| HIGHEST_RATING | 평점 내림차순, 작성 시각 내림차순, ID 내림차순 |
| LOWEST_RATING | 평점 오름차순, 작성 시각 내림차순, ID 내림차순 |

`size`는 기본 20, 범위는 1~50이다. 첫 페이지에는 `cursor`를 생략한다. `data.page_info.has_next=true`이면 `next_cursor`를 그대로 다음 요청에 전달한다. 숙소·정렬을 바꾸면 커서를 초기화한다. 마지막 페이지는 `next_cursor=null`이다. `current_size`는 현재 페이지의 항목 수이며 총 리뷰 수가 아니다.

조회 사이에 리뷰가 작성·수정·삭제되면 순서와 포함 여부가 달라질 수 있다. 특히 평점 변경은 평점순 정렬의 위치를 바꾼다. 커서는 목록의 고정된 스냅샷을 제공하지 않는다.

- `reviewed_at`은 최초 작성 UTC 시각이며 본문·평점 수정 후에도 유지한다. 과거 데이터의 시각·본문은 null일 수 있다.
- `reviewer`에는 작성자의 현재 ID·닉네임·프로필 이미지가 나온다. 과거 닉네임과 미설정 프로필 이미지는 null일 수 있다.
- `images`는 이미지가 없으면 빈 배열이다. 각 항목의 `id`는 이미지 삭제에 사용하며, 배열의 표시 순서는 보장하지 않는다.
- 목록은 리뷰 본문과 페이지 정보만 반환한다. 숙소의 총 리뷰 수·평균 평점은 숙소 응답의 `review_summary`에서 확인한다.

잘못된 정렬 값·숫자로 해석할 수 없는 경로 ID는 400/C004, 잘못된 커서는 400/C010, size의 형식·범위 오류는 400/C006이다.

## 수정과 삭제

`PATCH /api/v1/reviews/{reviewId}`는 **본문이 필수**다. 평점은 생략·null이면 유지하고 지정하면 1~5로 바꾼다. 평점만 바꾸려면 기존 본문도 함께 보낸다.

```json
{"content":"수정한 리뷰 내용입니다.","rating":4}
```

성공은 200과 `{"success":true,"data":{"id":201}}`다. 본문만 수정하면 평점 집계를 바꾸지 않는다. 평점 변경은 리뷰 수를 유지하면서 평균에 반영한다. 동시 수정·삭제는 같은 리뷰의 현재 상태와 평점을 기준으로 처리하여 집계에 중복 반영하지 않는다.

`DELETE /api/v1/reviews/{reviewId}`는 본문 없이 호출한다. 성공은 200과 `{"success":true}`다. 리뷰를 DELETE 상태로 바꾸고 공개 목록·평점 집계에서 제외한다. 첨부 이미지의 연결과 저장 파일까지 자동 삭제하는 동작은 아니다.

| 요청 | 조건 | HTTP / 코드 |
|---|---|---|
| 작성 | 활성 회원을 찾지 못함 | 404 / M001 |
| 작성 | 숙소가 없거나 PUBLISHED가 아님 | 404 / A001 |
| 작성 | 해당 숙소의 체크아웃 완료 예약 조건 미충족 | 403 / V003 |
| 작성 | 본인의 게시 리뷰가 이미 존재 | 409 / V004 |
| 수정·삭제·이미지 업로드 | 리뷰가 없거나 타인의 리뷰 | 404 / V001 |
| 수정 | 본인의 DELETE·HIDDEN 리뷰 | 403 / V005 |
| 삭제 | 본인의 DELETE·HIDDEN 리뷰. 삭제 재요청 포함 | 404 / V001 |

## 이미지 추가와 삭제

[공통 이미지 업로드 규칙](conventions.md#이미지-업로드)을 따른다. `multipart/form-data`에서 파일마다 `images` 파트를 반복한다. 파일 파트의 Content-Type은 `image/jpeg` 또는 `image/png`, 파일당 최대 10MiB, 요청 전체 최대 20MiB다. 전체 크기에는 multipart 헤더와 구분자도 포함한다. 현재 형식 검사는 파일 파트의 Content-Type을 기준으로 한다.

파일을 모두 검증한 후 업로드한다. 성공 응답의 `data.uploaded_images`에는 **이번 요청에 추가한** 이미지의 `id`, `image_url`이 나온다. 리뷰 ID는 생성 응답 또는 목록의 `reviews[].id`에서 얻는다.

`DELETE /api/v1/reviews/{reviewId}/images/{imageId}`는 본문 없이 호출한다. 업로드 응답이나 목록의 `images[].id`를 사용한다. 성공은 200과 `{"success":true}`다. 이미지가 없거나 타인의 이미지이면 403/V006이며, 본인 이미지지만 reviewId가 실제 소속과 다르면 400/C009다. 같은 삭제 요청을 다시 보내면 403/V006이다.

현재 이미지 추가·삭제는 리뷰가 DELETE·HIDDEN인지 별도로 제한하지 않는다. 이미지 삭제는 데이터베이스의 연결을 삭제하고 저장소 파일 삭제를 시도한다. 저장소 삭제 실패는 기록만 남기므로 200이 저장소 파일 삭제까지 보장하지는 않는다.

| 업로드 오류 | HTTP / 코드 |
|---|---|
| images 파트 누락 | 400 / C001 |
| 빈 파일 | 400 / I007 |
| 파일 Content-Type 오류 | 400 / I003 |
| 서비스에서 발견한 개별 파일 크기 초과 | 400 / I008 |
| 서버 multipart 크기 제한 초과 | 413 / I009 |
| multipart가 아닌 요청 | 415 / C011 |
| 파일 스트림 처리 실패 | 500 / I001 |

모든 변경 API는 세션이 없으면 401/M004다. 저장소·DB 장애 등 예상하지 못한 실패는 500/C003으로 처리될 수 있다.
