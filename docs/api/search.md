# 숙소 검색 API 사용 안내

`GET /api/v1/search/accommodations`는 로그인 없이 호출할 수 있다. 요청 본문은 없고 쿼리 이름은 **camelCase**, 응답 필드는 **snake_case**다. 필드와 오류 스키마는 [client.yaml](openapi/client.yaml)의 `검색` 태그에서 확인한다.

유효한 `SESSION_ID` 쿠키가 있으면 본인의 활성 위시리스트 저장 여부를 함께 반환한다. 세션이 없거나 만료됐어도 검색은 가능하며 `is_in_wishlist`는 모두 `false`다. 회원 ID를 직접 입력하지 않는다.

## 검색 조건

공백이 아닌 `destination` 또는 지도 좌표 4개 중 하나의 조건이 있어야 검색한다. 둘 다 없으면 가격·날짜·인원을 입력했어도 200과 빈 목록을 반환한다. 목적지와 지도 범위를 함께 입력하면 **두 조건을 모두 만족**하는 숙소를 검색한다.

| 쿼리 | 동작 |
|---|---|
| `destination` | 도시·구/군·도로·상세 주소·국가·숙소 이름·설명에 대한 텍스트 검색. 정확히 일치하는 지역 코드 조회가 아니며 공백만 있으면 생략으로 취급 |
| `minPrice`, `maxPrice` | 0 이상의 32비트 정수. 양 끝값을 포함하는 **1박 기본 가격** 범위. 둘 다 있으면 최소 ≤ 최대. 숙박 전체 요금·할인·수수료 기준이 아니며 통화 변환도 수행하지 않음 |
| `checkIn`, `checkOut` | 숙소 현지 날짜 `YYYY-MM-DD`. 함께 입력하거나 모두 생략. 체크아웃 > 체크인 |
| `adultOccupancy`, `childOccupancy` | 0 이상의 32비트 정수. 성인 + 아동이 최대 수용 인원 이내인 숙소. 성인이 생략되거나 0이면 **1명으로 보정**, 아동 생략은 0명 |
| `infantOccupancy`, `petOccupancy` | 0 이상의 32비트 정수. 유아와 반려동물은 성인 + 아동 합계에 포함하지 않고 각각 별도 수용 인원과 비교. 생략은 0 |
| `topLeftLat`, `topLeftLng`, `bottomRightLat`, `bottomRightLng` | 지도 좌상단·우하단 좌표. 4개를 함께 입력하거나 모두 생략. 위도 −90~90, 경도 −180~180, 유한한 숫자만 허용. 위쪽 위도 ≥ 아래쪽 위도 |
| `amenityTypes`, `accommodationTypes` | **현재 미지원. 입력해도 검색 조건에 반영되지 않음.** 이 값으로 편의시설·숙소 유형을 제한할 수 없음 |

지도 경도는 날짜 변경선을 가로지를 수 있다. 예를 들어 왼쪽 경도 170, 오른쪽 경도 −170은 날짜 변경선 양쪽의 좁은 영역을 뜻한다.

날짜를 지정하면 각 숙소 현지의 오늘부터 3개월 뒤까지의 예약 가능 기간에 포함되는 숙박만 검색한다. 체크인은 오늘 이상·3개월 뒤 미만, 체크아웃은 3개월 뒤 이하이며, `[checkIn, checkOut)`와 겹치는 예약이 검색 색인에 있는 숙소는 제외한다. 기존 예약의 체크아웃 날에 새로 체크인하거나, 기존 체크인 날에 체크아웃하는 것은 겹침이 아니다. 과거 날짜나 예약 가능 기간 밖의 날짜 자체를 400으로 거절하지는 않으며, 해당 기간을 수용하는 숙소가 없으면 200과 빈 목록이다. 날짜를 생략하면 예약 가능 여부는 필터링하지 않는다.

예를 들어 다음 요청은 서울 텍스트 검색 결과 중 1박 기본 가격 10만~20만, 성인 2명·아동 1명을 수용하는 숙소를 조회한다. 예시 가격은 색인에 저장된 각 숙소 통화의 숫자 그대로 비교한다.

```http
GET /api/v1/search/accommodations?destination=서울&minPrice=100000&maxPrice=200000&adultOccupancy=2&childOccupancy=1&page=0
```

## 페이지와 정렬

- `page`는 0부터 시작하고 기본값은 0이다. 음수나 정수로 해석되지 않는 값은 0, 해석 가능한 14 초과 값은 14로 보정한다.
- `size`는 입력값과 관계없이 **18**이다. 접근할 수 있는 페이지는 0~14, 최대 270개다.
- 검색 엔진의 기본 관련도 순서를 사용한다. `sort`를 입력해도 적용하지 않으며, 점수가 같은 숙소 간의 고정 순서는 보장하지 않는다. 지도만 검색할 때도 거리순·가격순이 아니다.
- `total_elements`는 검색 엔진이 반환한 전체 일치 건수다. 기본 집계 한도(10,000건)를 넘으면 정확한 전체 개수 대신 하한값일 수 있다. `total_pages`는 이 값으로 계산하므로 15를 초과할 수 있다.
- 실제 다음 페이지 요청 가능 여부는 **`has_next`**로 판단한다. 마지막 접근 가능 페이지 14에서는 더 많은 일치 결과가 있어도 `has_next=false`, `is_last=true`다.
- 현재 페이지가 비어 있어도 검색에서 확인한 `total_elements`·`total_pages`는 유지한다. 예를 들어 전체 2건에서 `page=1`을 요청하면 목록은 비어 있고 전체 건수는 2다.

검색 조건 자체가 없거나 일치 결과가 없는 첫 페이지 응답은 다음과 같다.

```json
{
  "success": true,
  "data": {
    "stay_search_result_listing": [],
    "page_info": {
      "page_size": 18,
      "current_page": 0,
      "total_pages": 0,
      "total_elements": 0,
      "is_first": true,
      "is_last": true,
      "has_next": false,
      "has_previous": false
    }
  }
}
```

## 결과 표시와 최신성

결과 항목의 `id`는 숙소 ID다. 이름·대표 사진·숙소 유형·기본 가격·통화·주소·좌표·리뷰 집계는 검색 색인의 값이다. 과거 색인에 이름·사진·유형·가격·통화가 없으면 `null`일 수 있고, 주소·좌표 객체도 내부 필드가 `null`일 수 있다. 리뷰 집계가 없으면 0건·0점이다. `is_in_wishlist`는 로그인 회원의 현재 활성 위시리스트를 기준으로 조회한다.

검색 색인은 비동기로 갱신된다. 색인상 `PUBLISHED`인 숙소만 검색하지만, 공개 상태·가격·리뷰·예약 가능 여부가 실제 변경 직후에는 잠시 다를 수 있다. **검색 결과는 예약 가능 확정이 아니다.** 예약 체크아웃에서 현재 숙소·가격·쿠폰·재고를 다시 확인한다.

## 주요 오류

| 상태·코드 | 상황 |
|---|---|
| 400/C001 | 지도 좌표 누락·범위·위아래 순서 오류, 음수 가격·인원, 가격 역전, 날짜 한쪽 누락·순서 오류, 숫자·날짜 해석 실패 |
| 503/SE001 | 검색 엔진 연결·검색 처리 실패. 빈 검색 결과와 구분하며 `Retry-After` 헤더는 제공하지 않음 |
| 500/C003 | 그 밖의 서버 처리 오류 |

세션이 없거나 만료된 경우는 401 오류가 아니다. 편의시설·숙소 유형 입력은 무시되며 오류로 거절하지 않는다.
