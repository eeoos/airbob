# 매출 통계 API

필드·타입·오류 예시는 [관리자 OpenAPI](openapi/admin.yaml)의 `매출 통계`에서 확인한다.
두 API 모두 로그인 세션과 현재 ACTIVE ADMIN 권한이 필요하다. Swagger UI에서는 먼저 로그인하며,
`SESSION_ID`나 회원 ID를 입력 매개변수로 전달하지 않는다.

## 조회와 재집계

| 목적 | 요청 | 필수 쿼리 | 성공 응답 |
|---|---|---|---|
| 일별 사전 집계 조회 | `GET /api/v1/admin/stats/revenue` | `from`, `to` | 200, `data`에 기간·출처·일별 결과 |
| 기간 재집계 | `POST /api/v1/admin/stats/revenue/recompute` | `from`, `to` | 200, `{"success":true}` |

`from`과 `to`는 **UTC 날짜** `YYYY-MM-DD`이며 양쪽 날짜를 모두 포함한다.
시작일은 종료일 이하여야 하고, 연도는 1000~9999여야 한다. 같은 날·오늘·미래 날짜도 허용한다.
두 요청 모두 본문이 없고, 페이지네이션·호스트·숙소·통화 필터를 지원하지 않는다.

조회는 실시간 결제 원장이 아닌 **마지막으로 저장된 사전 집계 결과**를 반환한다.
`source`는 항상 `stats`이고, `from`·`to`는 요청한 기간을 그대로 반환한다.
`items`는 날짜 오름차순이다. 집계 행이 없는 날짜를 0으로 채우지 않으며, 결과가 전혀 없으면 빈 배열이다.
따라서 어떤 날짜가 빠졌다는 사실만으로 거래가 없었는지 아직 집계하지 않았는지를 구분할 수 없다.

```http
GET /api/v1/admin/stats/revenue?from=2027-01-01&to=2027-01-03
```

```json
{
  "success": true,
  "data": {
    "from": "2027-01-01",
    "to": "2027-01-03",
    "source": "stats",
    "items": [
      {"date":"2027-01-01","gross_amount":150000,"refund_amount":20000,"net_amount":130000,"payment_count":2,"refund_count":1},
      {"date":"2027-01-03","gross_amount":0,"refund_amount":50,"net_amount":-50,"payment_count":0,"refund_count":2}
    ]
  }
}
```

위 예시는 가상의 집계 결과이며, 1월 2일에 해당하는 집계 행은 없다.

## 금액과 건수의 기준

| 필드 | 계산 기준 |
|---|---|
| `gross_amount` | `CONFIRM` 원장 행의 `amount` 합계. 원장의 `created_at` UTC 날짜 기준 |
| `refund_amount` | `CANCEL`·`PARTIAL_CANCEL` 원장 행의 `cancel_amount` 합계. `canceled_at` UTC 날짜 기준이며, 값이 없으면 `created_at` 사용 |
| `net_amount` | `gross_amount - refund_amount`. 수수료를 차감한 정산액이 아니며 음수도 가능 |
| `payment_count` | 집계 대상 `CONFIRM` 원장 행 수 |
| `refund_count` | 집계 대상 `CANCEL`·`PARTIAL_CANCEL` 원장 행 수 |

승인일은 PG 승인 시각이나 숙박일이 아닌 **원장이 생성된 날짜**다.
환불은 원래 승인 날짜에서 빼지 않고 위 기준의 환불 날짜에 반영한다.
같은 예약의 부분 환불이 여러 번 기록되면 각각 한 건으로 계산한다. 금액이 null인 과거 행은 금액 0,
건수 1로 반영한다. 실패·취소 실패·가상계좌 발급 원장 행은 집계하지 않는다.

집계는 예약 행과 연결되는 원장만 대상으로 하며 별도의 결제 상태·예약 상태·숙소 공개 상태 필터는 없다.
숙소별 집계를 날짜별로 합산하며, 통화를 구분하거나 환산하지 않는다. 응답에 통화 필드도 없으므로
여러 통화가 섞인 데이터를 특정 통화의 총매출로 해석하면 안 된다.

## 갱신 시점과 실패 처리

자동 집계는 매일 **04:00 UTC(한국 시각 13:00)**에 전일 하루를 처리한다.
과거 날짜로 늦게 기록된 환불 등은 그 날짜를 수동으로 재집계해야 조회에 반영된다.
오늘을 재집계해도 그 이후 발생하는 거래가 자동으로 실시간 반영되지는 않는다.

재집계는 날짜마다 기존 결과를 삭제한 뒤 원장에서 다시 생성한다. 동일한 원장으로 반복해도
금액·건수가 누적되지 않으며, 거래가 없어진 날짜는 기존 집계 행도 제거된다.
**전체 요청 기간이 한 트랜잭션**이어서 중간 실패 시 모든 날짜의 변경이 롤백된다.
실패 직전 날짜까지 부분 완료되는 방식이 아니다.

요청은 동기로 처리하며 200은 재집계가 완료됐다는 뜻이다. 작업 ID·진행률·처리 건수는 반환하지 않는다.
기간 길이의 별도 상한은 없고 긴 기간일수록 처리 시간이 길어진다. 동시 재집계 등의 DB 오류가 발생하면
500으로 실패할 수 있다. 실패 원인을 해소한 뒤 같은 기간을 다시 실행할 수 있다.

## 오류

| 상태/코드 | 조건 |
|---|---|
| 400/C001 | 필수 날짜 누락·빈 값, 시작일이 종료일보다 늦음, 지원 연도 범위 밖 |
| 400/C004 | 날짜 형식 오류·존재하지 않는 날짜 |
| 401/M004 | 유효한 로그인 세션 없음 |
| 403/M006 | 현재 ACTIVE ADMIN 권한 없음 |
| 500/C003 | DB 집계 실패 등 서버 처리 오류 |
