# 최근 본 숙소 API 사용 흐름

최근 본 숙소 API 3개는 모두 로그인이 필요하다. 로그인 응답의 HttpOnly `SESSION_ID` 쿠키를 브라우저가 자동 전송한다. 회원 ID나 쿠키 값을 요청 폼에 직접 입력하지 않는다. 요청·응답 구조와 오류 예시는 [client.yaml](openapi/client.yaml)의 `최근 본 숙소` 태그에서 확인한다.

## 기록·조회·삭제

| 작업 | 메서드와 경로 | 성공 응답 |
|---|---|---|
| 조회 기록 추가·갱신 | `POST /api/v1/members/recently-viewed/{accommodationId}` | 200, `{"success":true}` |
| 목록 조회 | `GET /api/v1/members/recently-viewed` | 200, `data.accommodations`·`data.total_count` |
| 기록 삭제 | `DELETE /api/v1/members/recently-viewed/{accommodationId}` | 200, `{"success":true}` |

`accommodationId`에는 **숙소 ID**를 넣는다. 별도의 기록 ID나 위시리스트 연결 ID가 아니다. POST와 DELETE의 요청 본문은 없다.

숙소 상세 조회만으로 최근 본 기록이 자동 추가되지는 않는다. 화면에서 최근 본 숙소로 남길 때 POST를 별도로 호출한다. 같은 숙소를 다시 기록하면 기존 항목의 마지막 기록 시각을 갱신하며 중복 항목을 만들지 않는다. 시각은 서버 현재 시각을 사용한다.

기록 추가 시에는 숙소의 존재·공개 여부를 확인하지 않는다. 따라서 POST 200이 목록 노출을 보장하지는 않는다. 실제 목록 조회 시 현재 공개된 숙소만 표시하고 유효하지 않은 기록을 정리한다.

삭제는 해당 회원의 기록만 제거한다. 숙소 자체, 다른 회원의 기록, 위시리스트 저장 상태에는 영향을 주지 않는다. 기록이 없거나 이미 삭제했어도 200이다.

## 최대 개수와 보관 기간

- 회원별 최대 **100개**의 숙소 기록을 보관한다. 새 기록으로 한도를 넘으면 오래된 기록부터 제거한다. 동시에 기록해도 추가·개수 제한·만료 갱신을 함께 처리한다.
- POST를 호출할 때마다 **목록 전체의 만료가 7일 뒤로 갱신**된다. 같은 숙소를 다시 기록해도 갱신한다.
- 개별 항목이 각각 7일 후에 삭제되는 방식은 아니다. 새 숙소를 계속 기록하면 오래된 항목도 100개 한도 안에서 남을 수 있다.
- GET과 DELETE는 만료 시각을 연장하지 않는다. 마지막 항목을 삭제하면 빈 목록이 되고, 마지막 POST 후 7일간 새 기록이 없으면 전체 목록이 만료된다.

## 목록의 순서와 표시 값

최근 기록 시각 내림차순이며, 같은 밀리초인 경우에는 숙소 ID **문자열** 내림차순이다. 예를 들어 같은 시각의 ID `9`, `31`, `10`은 이 순서로 반환된다. 페이지·커서·크기 매개변수는 없으며 현재 표시 가능한 기록 전체를 반환한다.

현재 공개 상태가 아닌 숙소(`DRAFT`, `UNPUBLISHED`, `DELETED`)와 존재하지 않는 숙소는 응답에서 제외하고 해당 회원의 기록에서도 제거한다. 다시 공개되더라도 제거한 기록이 자동 복원되지는 않는다.

| 응답 필드 | 의미 |
|---|---|
| `viewed_at` | 이 회원이 마지막으로 기록한 서버 UTC 시각(`Z`), 밀리초 정밀도 |
| `accommodation_id` | 숙소 ID |
| `accommodation_name` | 현재 숙소 이름. 과거 데이터는 `null`일 수 있음 |
| `thumbnail_url` | 현재 대표 사진. 없으면 `null` |
| `address_summary` | 현재 주소 요약. 주소가 없는 과거 숙소도 객체는 반환하고 각 필드는 `null` |
| `review_summary` | 현재 게시된 리뷰 수와 평균 평점. 리뷰가 없으면 0건·0점 |
| `is_in_wishlist` | 본인의 활성 위시리스트 중 하나라도 해당 숙소를 포함하는지 여부 |
| `total_count` | 이번 `accommodations` 배열의 길이. 정리된 비공개·삭제 기록은 포함하지 않음 |

숙소·주소·리뷰·찜 상태는 기록 당시의 사본이 아니라 조회 시점의 현재 값이다. 최근 본 목록을 읽어도 `viewed_at`은 갱신되지 않는다.

기록이 없거나 만료됐거나 표시 가능한 숙소가 없으면 다음과 같이 반환한다.

```json
{
  "success": true,
  "data": {
    "accommodations": [],
    "total_count": 0
  }
}
```

## 주요 오류

| 상태·코드 | 상황 |
|---|---|
| 401/M004 | 세션이 없거나 만료됨 |
| 400/C004 | POST·DELETE의 숙소 ID를 64비트 정수로 해석할 수 없음 |
| 500/C003 | 기록 저장소나 조회 처리 중 서버 오류 |

존재하지 않는 숙소 ID의 기록·삭제는 404가 아니다. 기록은 조회 시 정리하며, 삭제는 기록 유무와 관계없이 성공한다.
