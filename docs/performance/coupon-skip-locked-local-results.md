# 쿠폰 SKIP LOCKED 구현과 로컬 반복 측정

측정일: 2026-10-09~11. 환경은 `local`이다. AWS 및 운영 트래픽에서 측정한 결과가 아니다.

## 후보별 풀 격리 수준을 맞춘 시나리오 재검증 · 2026-10-10~11

앱 1개·풀 10·동일 V30 JAR에서 5가지 방식 × 8개 시나리오 × 5회 반복을 완료했다.
RR 후보는 RR 기본 풀, RC 후보는 RC 기본 풀을 사용하고 후보마다 실제 연결 10개를 확인했다.
200회 본 측정 중 유효 168회, 지연·처리율을 포함한 전체 기준 통과 155회다.
32회는 호스트 압력 또는 부하 생성 누락으로 무효였으며, 유효하지만 기준에 실패한 실행은 13회다.
워밍업 200회는 본 측정에 합산하지 않았다.

| 방식 | 400 RPS·60초 통과 / 유효 / 전체 | 650 RPS·60초 통과 / 유효 / 전체 | 1,000 RPS·5초 급증 포함 시나리오 통과 / 유효 / 전체 |
|---|---:|---:|---:|
| 조건부 UPDATE | 0 / 4 / 5 | 0 / 0 / 5 | 0 / 0 / 5 |
| 대리 키 RR | 5 / 5 / 5 | 3 / 3 / 5 | 2 / 3 / 5 |
| 대리 키 RC | 4 / 5 / 5 | 3 / 3 / 5 | 1 / 3 / 5 |
| 복합 키 RR | 4 / 4 / 5 | 4 / 5 / 5 | 0 / 1 / 5 |
| 복합 키 RC | 5 / 5 / 5 | 4 / 4 / 5 | 0 / 2 / 5 |

400 RPS에서 조건부 UPDATE의 유효 4회는 모두 p95 기준에 실패했다(1,021~1,324ms).
대리 키 RR은 5회 모두 통과했고 p95는 12.35~141.04ms였다.
조건부 UPDATE에서는 매회 `coupon/PRIMARY` 잠금 대기가 관측됐고,
같은 400 RPS의 SKIP LOCKED 네 후보에서는 행 잠금 대기가 0회였다.
공유 카운터 경합을 제거한 효과는 확인했지만, 이 수치로 최대 처리량 개선율을 만들지는 않는다.

키와 격리 수준 사이에서는 사전 합의한 반복 지연 개선 기준을 충족한 비교가 없었다.
현재 기본값인 **대리 키 RR을 유지**한다. 이것이 가장 빠르다는 판정은 아니며,
650 RPS와 급증 구간의 무효 실행 때문에 단일 후보의 안정적 한계 처리량도 확정하지 않는다.
급증 구간은 마지막 응답이 끝나는 시간까지 포함한 처리율을 사용하므로,
모든 요청을 보냈고 p95가 낮아도 별도 구간 처리율 기준에 실패할 수 있다.

본 측정 실제 요청은 2,756,721건이며 성공 발급 2,384,285건, 품절 249,975건,
중복 요청 거절 122,461건이다. 초과 발급·중복 소유·재고 유실·예상 외 응답과
관측된 교착 상태는 0건이다. 예정 요청 2,812,500건과 실제 요청 차이는 55,779건이며,
`dropped_iterations` 합계 55,766건과의 13건 차이도 원본 그대로 보존했다.
실행 경계의 정확한 차이 원인은 별도 규명하지 않았으며, 완료 요청의 서버·클라이언트 수는 일치했다.

마지막 측정과 임시 자원 정리는 완료됐지만 자동 후처리 프로세스가 사라져 집계·개발 컨테이너 복구가
남아 있었다. 원본 완료 결과와 정리 기록으로 상태를 확인한 뒤 기존 컨테이너 11개를 복구했다.
상위 프로세스 종료 원인과 5회차 종료 코드는 미확인으로 남겼고 복구 전 상태도 보존했다.
