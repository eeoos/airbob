# API 분리·Spring Data native query 재측정 근거

[상세 보고서](../../coupon-skip-locked-local-results.md)의 C·B 재측정 자료다.
앱 커밋은 `b2c6ec6542413807ad9e2923b2ee3a3632bef579`, Flyway V29이고 JAR SHA-256은
`05cd3f7ce7a2c4df3fc0197c4dbeebb5e816b68252b0fe50e3d18d084d57ef8f`다.
현재 소스의 V30·UTC 변경은 이 성능 측정에 포함하지 않았다.

- C: `local-20261010-185313-8051` — 20초, 2라운드의 적응형 탐색. 본 측정 36회·워밍업 36회.
- B: `local-20261010-193711-8b8c` — 500 RPS·60초·2라운드, 5개 방식. 본 측정 10회·워밍업 10회.

둘 다 앱 1개, 풀 maximum/minimumIdle 10, 초기 재고 30,001개, 실제 로그인 회원 30,001명이다.
새 MySQL 8.4.11·Redis 7.2와 같은 macOS 호스트에서 실행했다. 서버·DB·부하 발생기를 분리한 AWS 측정이 아니다.
측정 중 빌드와 기능 테스트를 실행하지 않았다. 앞선 C와 B 사이에 UTC 코드의 기능 검증을 수행했다.

| 파일 | 내용 |
|---|---|
| `comparison.json` | 실행 메타데이터, 모든 본 측정·워밍업, 회차별 결과·판정·계측·정리·원본 해시 |
| `raw.ndjson.gz` | 클라이언트, SQL, 풀, DB, 호스트, 재고와 정리 자료의 허용 목록 |
| `harness-sources.ndjson.gz` | 각 실행에서 고정한 V29용 Python/k6 소스와 파일별 해시 |
| `validation.json` | 요청·재고·SQL·획득 수·바이너리/소스 일치와 리소스 정리 검증 |
| `utc-validation.json` | 별도 V30·UTC 코드의 백엔드/프론트 기능 검증; 성능 측정 코드와 구분 |
| `SHA256SUMS` | 이 디렉터리 파일의 해시(자신 제외) |

본 측정 총 46회, 실제 발급 577,360건이다.
유효 33회·전체 기준 통과 25회이며 무효·실패 회차도 모두 보존했다.
오류·중복·초과 발급·교착 상태는 관측되지 않았다. 요청 누락과 지연 실패 및 호스트 압력은 존재한다.
기본 기준은 p95 ≤ 500ms, p99 ≤ 1,000ms, 목표 대비 처리율 ≥ 99%, 누락·오류 없음과 호스트 관측 유효성이다.

매 본 측정 요청의 Hibernate SQL은 DB 4개, SKIP 6개, 커넥션 획득은 1회다.
SQL 수는 발급 경로의 Hibernate 계측이며 드라이버 프로토콜·세션 설정 명령 전체의 수가 아니다.
운영 V1은 여전히 전략 조회를 수행한다. API 경로와 저장소 구현을 함께 바꿔 개별 변경의 효과를 분리하지 않았다.
서로 다른 시점의 기존 풀 실험이나 812 RPS 탐색과 통계를 합치지 않는다.

압축 파일은 NDJSON이다. 각 줄의 `path`, `sha256`, `text`로 원본 UTF-8 바이트를 확인할 수 있다.
`metadata.harnessSha256`은 실행 소스, `sourceArtifactSha256`은 원본 자료별 해시다.
B는 C와 같은 JAR 및 V29 실행기를 별도로 보존한 디렉터리에서 사용했다.
그 뒤 UTC 코드가 커밋됐지만 실행 중인 앱과 고정 소스를 교체하지 않았다.
현재 V30 실행기에 이 V29 JAR 또는 manifest를 넣지 않는다.

비밀번호·토큰·세션·런타임 비밀 설정·애플리케이션 로그·로그인 기록·JAR는 저장소 묶음에서 제외했다.
전용 앱·DB·Redis는 모두 정리했고 기존 개발 컨테이너는 유지했다.
