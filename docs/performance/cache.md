# 숙소 상세 Redis 캐시 측정 결과

2026-10-10~11 AWS에서 비로그인 숙소 상세 조회를 측정했다. 실제 서비스 트래픽이 아닌 부하 테스트다.
비교용 앱 프로필·스위치는 측정 완료 후 제거했다. [k6 스크립트와 실행 가이드](../../load-test/k6/cache/MEASUREMENT.md)는
측정 방법의 근거로 보존하며, 재현에는 아래에 기록한 당시 앱·이미지·데이터셋을 함께 사용한다.

## 캐시 도입 효과

앱 `c6i.large` 1대(2 vCPU·메모리 3GiB·heap 1,536MiB), Hikari 풀 10개,
MySQL `db.t3.small`, 전용 Redis `t3.small`, 부하 발생기 `c6i.xlarge`를 사용했다.
동일 이미지·데이터에서 캐시만 OFF/ON으로 전환했다. 리뷰 요약 반정규화는 양쪽 모두 적용했다.

| 비교 | 캐시 OFF | 캐시 ON |
|---|---:|---:|
| 반복 검증한 최대 지속 처리량 | 1,100 RPS | 5,000 RPS |
| 해당 부하의 실제 완료 RPS | 1,099.98~1,099.99 | 4,998.17~4,998.74 |
| 해당 부하의 p95 | 941.5~1,143.6ms | 126.0~188.2ms |
| 별도 100 RPS 비교의 p95 대표값 | 9.1ms | 3.5ms |

처리량은 20개 숙소를 균등 반복 조회하고 ON 캐시를 예열한 조건이다.
각 후보를 300초씩 3회 측정해 모두 통과한 최고 단계를 선택했다.
통과 기준은 응답 오류·본문 불일치·k6 미시작 요청 0건, 완료 건수·실제 RPS가 목표의 99% 이상,
부하 발생기 CPU 90% 미만·가용 메모리 15% 이상이다. p95와 앱 CPU는 상한 판정 기준에 넣지 않았다.

OFF 1,200 RPS는 2/3회, 1,300 RPS는 1/3회, 1,400 RPS는 0/3회 통과했다.
ON 5,200 RPS는 1/3회 통과했다. 1,100/5,000 RPS는 측정한 단계 중 반복 검증값이다.

- OFF 1,100 RPS의 DB CPU는 약 80%, 1,400 RPS는 약 89~92%였다. 후자의 커넥션 획득 평균 대기는 약 133~137ms였다.
- 커넥션 획득 타임아웃은 0건이었다. 처리량 미달을 DB 커넥션 타임아웃으로 설명하지 않는다.
- ON은 예열 후 측정 구간의 DB 로딩·SELECT가 0회였고, 5,000 RPS에서 앱 CPU가 약 99%였다.
- 100 RPS 지연 비교는 단일 숙소·60초·2회로 별도 진행했다. p95는 9.78→3.44ms, 8.51→3.53ms이며 대표값 9.1→3.5ms는 회차 p95의 평균을 반올림한 값이다. 전체 요청을 합친 p95는 아니다.

최초 요청 건수 판정은 명목 건수와 정확히 일치하는 조건이었다. 종료 경계의 집계 차이를 확인한 뒤
기존 실제 RPS 기준과 같은 99% 기준을 건수에도 적용해 OFF/ON 전체를 재판정했다.
원자료와 최초 판정은 보존했다. 요청 누락이 있었던 회차의 탈락 판정은 바뀌지 않았다.

## 동시 미스와 Redis 장애

| 조건 | DB 로딩 OFF → ON | 감소율 | 회차 p95 중앙값 OFF → ON |
|---|---:|---:|---:|
| 앱 2대·동일 숙소 300건 버스트, 분산 락·Double Check 비교 | 300회 → 1회 | 99.7% | 638ms → 392ms |
| 앱 1대·Redis 미응답·동일 숙소 300건 버스트, JVM 병합 비교 | 300회 → 19회 | 93.7% | 2,160ms → 2,177ms |

각 조건을 3회 측정했다. 분산 락 비교에서는 캐시 ON·로컬 병합 OFF로 고정하고 매회 캐시를 비웠다.
각 VU의 HTTPS 연결만 먼저 예열한 뒤 요청했으며, 두 앱의 miss·락 시도를 확인했다.
permit과 TTL 정책은 대조군에도 유지했다. 락 ON의 DB 로딩은 세 번 모두 1회였다.

장애 실험은 동일한 Redis 미응답·timeout 조건에서 로컬 병합만 전환했다.
병합 ON의 DB 로딩은 19·15·27회였고, 표는 중앙값 19회를 사용했다. 전체 요청 오류는 0건이었다.
병합은 DB 부하를 줄였지만 Redis 응답 대기는 남았으며, 이 실험에서 p95 개선은 확인하지 못했다.
