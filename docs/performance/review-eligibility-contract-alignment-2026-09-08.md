# 후기 작성 가능 여부 계약 정렬

대상은 게스트 예약 상세 GET /api/v1/profile/guest/reservations/{uid}의
can_write_review와 이를 사용하는 예약 상세 버튼 및 후기 작성 화면이다.
프론트 작업 브랜치는 codex/editable-booking-review다.

## 확인한 오류와 수정

기존 프론트는 서버가 can_write_review=true를 반환해도 CONFIRMED 상태와
브라우저 현지 날짜·시각을 추가로 검사했다. 이 때문에 취소 실패 후 유효하게
유지된 예약(CANCELLATION_FAILED)과 기기 시계가 느린 경우 작성 버튼이 숨겨졌다.
프론트의 상태·시각 재판정을 제거하고 서버 boolean을 사용하도록 정렬했다.
예약 상세와 후기 작성용 mapper 모두 누락·문자열 등 boolean이 아닌 값은 거부한다.

백엔드 상세 조회는 숙소 공개 여부를 검사하지 않아 실제 작성 API가 거부할
비공개·삭제된 숙소에서도 true를 반환했다. 이미 함께 읽은 숙소의 PUBLISHED
여부를 조건에 추가했다. 권한 판단과 응답 server_time에는 같은 Instant를 사용한다.

| 조회 시점 조건 | can_write_review | 후기 존재 SELECT |
|---|---|---|
| 숙소가 PUBLISHED가 아님 | false | 생략 |
| 예약이 CONFIRMED / CANCELLATION_FAILED가 아님 | false | 생략 |
| 체크아웃 시각이 server_time보다 늦음 | false | 생략 |
| 위 조건을 통과하고 같은 숙소·회원의 PUBLISHED 후기가 있음 | false | 실행 |
| 위 조건을 통과하고 PUBLISHED 후기가 없음 | true | 실행 |

체크아웃 시각과 server_time이 같으면 작성 가능 후보에 포함된다. 기존 정책인
숙소·회원 단위의 게시된 후기 중복 판정을 유지한다. 삭제·숨김된 후기의 취급이나
실제 후기 작성 API의 승인 조건은 변경하지 않았다. 조회 응답은 조회 시점의 안내이며
최종 작성 요청은 숙소 상태, 본인의 완료된 숙박, 기존 후기를 다시 검증한다.

## 조회 분리 판단

- 예약 상세는 이미 조회한 예약·숙소의 상태와 체크아웃 시각을 사용한다.
  작성할 수 없는 예약에서는 후기 테이블에 접근하지 않는다. 작성 가능 후보에만
  존재 조회를 유지한다. 이 조건부 조회를 무조건적인 후기 JOIN으로 바꿀 근거는 없다.
- 후기 작성 화면은 같은 게스트 예약 상세 API를 재조회해 숙소명·주소·숙박 기간과
  최신 권한을 얻는다. 별도 권한 API를 추가하지 않았다. 상세에서 작성 화면으로
  이동하는 사이 권한이 바뀌면 작성 폼을 표시하지 않는 동작을 브라우저로 검증한다.
- API·SQL·인덱스 구조는 유지했다. 변경한 백엔드 조건은 이미 fetch join한 숙소
  상태를 사용하므로 추가 조회가 없고, 비공개 숙소의 후기 존재 조회는 줄어든다.
  쿼리 실행계획이나 응답 시간 개선을 측정한 결과는 아니다.

## 검증

- 백엔드 관련 테스트 52개 통과, 건너뛴 테스트 없음.
- 서비스 회귀: 체크아웃 직전·정확한 시각, 전체 예약 상태, 기존 후기, 공개되지 않은
  숙소의 작성 가능 여부와 불필요한 후기 존재 조회 생략.
- 실제 MySQL: 전체 예약 상태별 완료 숙박 판정, 체크아웃 직전 마이크로초 경계,
  타인 예약으로 작성 자격을 얻지 못하는 조건.
- 작성 서비스: 숙소 비공개 전환, 완료 숙박 없음, 조회 이후 게시된 후기 발생 시
  실제 작성과 집계·이벤트 쓰기를 거부하는 기존 동작.
- [공유 JSON](../../src/test/resources/contracts/guest-reservation-reviewable.json):
  실제 GuestDetail DTO 직렬화를 검증하고 프론트의 두 mapper 및 브라우저에서 소비.
  fixture의 true/false 전달 검증과 서비스의 권한 계산 검증은 별도 테스트다.
- 프론트: 관련 20개 파일의 135개 테스트와 Chromium 시나리오 6개 통과.
  느린·빠른 기기 시계, 작성 완료 후 버튼 제거, 작성 화면 진입 시 권한 재확인을 포함한다.
- 앱·테스트·E2E 타입 검사, 변경 파일 lint·포맷 검사, 두 저장소의 fixture 일치 확인 통과.

브라우저 검증은 프로덕션 빌드와 합성 API 응답을 사용했다. 구동 중인 백엔드에
연결해 실제 후기를 등록한 HTTP 통합 검증은 수행하지 않았다.
