# 호스트 편집 정책 조회·저장 계약 정렬

대상은 호스트 숙소 상세 GET /api/v1/profile/host/accommodations/{id}의 policy와
편집 PATCH /api/v1/accommodations/{id}의 occupancy_policy_info다.
프론트는 codex/editable-booking-review에서 수정했다.

## 확인한 오류

1. 정책이 없을 때 백엔드는 각 필드가 null인 policy 객체를 반환한다. 프론트는
   policy 객체 자체가 null인지만 검사해 기본값 저장 여부를 정했다. 화면에
   최대 인원 1·유아 불가·반려동물 불가가 표시되어도 PATCH에는 정책이 빠졌다.
2. 일부 필드만 null인 정책도 같은 이유로 보완 저장되지 않았다.
3. 백엔드 updateOccupancyPolicy는 정책이 없을 때만 생성했다. 이미 정책이 있으면
   수정 요청을 무시하여 저장 성공 후 다시 조회해도 예전 값이 반환됐다.
4. 프론트는 유아·반려동물 수량을 체크박스로 표시한다. 최대 인원만 바꿔도
   기존 양수 수량을 모두 1로 변환하여 저장할 수 있었다.

## 변경한 동작

| 서버에서 읽은 정책 | 편집·저장 동작 |
|---|---|
| 정책 자체가 null 또는 모든 필드가 null | 기존 화면 기본값 1 / 0 / 0을 저장 |
| 일부 필드가 null 또는 누락 | 해당 필드의 화면 기본값을 저장하고 나머지 수량 보존 |
| 완전한 정책을 변경하지 않음 | 정책 PATCH 생략 |
| 최대 인원만 변경 | 기존 유아·반려동물 수량을 보존 |
| 유아·반려동물 체크 해제 | 해당 수량 0 저장 |
| 기존 수량이 0 또는 누락인데 체크 설정 | 해당 수량 1 저장 |
| 기본값 저장 완료 후 재진입 | 정책을 다시 수정하지 않으면 추가 정책 PATCH 없음 |

기존 API 응답 형태는 유지했다. read model은 필드별 null을 보존하고 화면의
기본값이 아직 저장되지 않았는지를 판정한다. 편집 화면은 마지막으로 확인된
정책 수량을 보관하여 체크박스로 표현하면서도 기존 수량을 잃지 않는다.

백엔드는 기존 정책 엔티티의 필드를 갱신한다. 동일 정책 행과 FK를 유지하며
JPA 변경 감지로 저장한다. occupancy_policy_info를 생략하면 기존 정책을 유지한다.
기존 숙소 잠금, 변경 이력, 게시 숙소의 검색 갱신 이벤트와 상세 캐시 무효화 흐름을
사용한다. 인덱싱 구현이나 인덱스·스키마는 변경하지 않았다.

## 조회 구조 판단

호스트 상세는 주소·인원 정책처럼 한 숙소에 하나인 정보를 fetch join으로 읽는다.
정책은 편집 초기화와 기본값 저장 판단에 모두 필요하므로 이 결합을 유지한다.
다건 관계인 편의시설과 이미지는 따로 조회해 두 목록을 JOIN했을 때 생기는
행 중복을 피한다. 이번 수정은 추가 조회를 요구하지 않는다.

현재 편집 mapper가 소비하지 않는 후기 요약·호스트·좌표는 별도의 조회 축소 후보다.
그중 후기 요약은 별도 SELECT도 실행된다. 이 단계에서는 정책 저장의 정확성을
고정했고, 해당 필드 제거 및 조회 축소는 다음 변경으로 분리한다.

## 검증 결과

- 백엔드 테스트 44개 통과, 건너뛴 테스트 없음.
- 실제 MySQL에서 정책 생성, 같은 행의 수정, 부분 누락 보완, 정책을 생략한 수정,
  별도 트랜잭션의 호스트 재조회, 수정 롤백을 검증했다.
- 게시 숙소의 기존 정책 수정에도 검색 갱신 요청과 캐시 무효화가 실행되는지 검증했다.
- [공유 JSON fixture](../../src/test/resources/contracts/host-policy-contracts.json)는
  실제 HostDetail.policy의 없음·부분 누락·완전한 상태를 직렬화한 계약이다.
  프론트 fixture와 내용이 같으며 전체 HTTP 응답을 나타내지는 않는다.
- 프론트 관련 14개 파일, 179개 테스트 및 Chromium 시나리오 11개 통과.
- 앱·테스트·E2E 타입 검사와 변경 파일 lint·포맷 검사 통과.

브라우저 검증은 프로덕션 빌드와 합성 API를 사용했다. 실제 서버에 연결한 HTTP
통합 검증이나 조회 성능·실행계획 측정은 수행하지 않았다.
