# 글로벌 B 데이터와 로컬 개발 환경 검증

예약 약 1천만 건을 포함한 글로벌 B 데이터를 생성·복원하고, 평소 개발 환경에서 로그인·조회·검색·변경 전달까지 확인했다. 대용량 데이터의 재현성, 숙소 현지 날짜와 UTC의 일치, 재고 초기화 비용, 제한된 로컬 디스크가 주요 과제였다. 공개 수치와 원본 근거의 SHA-256은 [검증 요약 JSON](global-b-evidence-summary.json)에 기록했다.

변경은 세 부분이다.

- **날짜 정확성:** 좌표로 결정한 시간대를 실제 Java·Python 런타임의 규칙과 대조하고, 정해진 기대값을 통과하지 못하면 실행을 차단한다. 덤프의 예약 날짜·시각도 독립적으로 검사했다.
- **재고 초기화:** 숙소마다 누락 날짜를 읽고 쓰는 비용을 줄이도록 범위 확인과 INSERT를 묶음 처리했다. 기존 재고의 상태·소유권을 덮어쓰지 않으며, 준비가 끝나기 전에 앱의 readiness가 열리지 않는 조건을 유지했다.
- **복원과 인수:** 업무 DB 하나를 순차 사용하면서 압축 덤프를 스트리밍 복원하고, 전체 행·DDL·SHA를 확인했다. 검색은 native snapshot을 별도 Elasticsearch에 복원해 모든 문서의 ID·필드와 매핑을 비교했다. 마지막에는 검증된 MySQL 볼륨을 일반 Compose 환경으로 연결했다.

2026-09-12 13:06 KST의 로컬 완료 기록은 다음과 같다.

**225,303,464행의 전체 지문은 재고 준비 후 동결된 native 인수 시점의 값이다.** 이후 일반 개발 DB의 쓰기를 열고 새 날짜의 재고를 보충했으므로, 이를 현재 DB의 고정 행 수로 해석하면 안 된다. 대표 계정 3개만 사용 가능으로 표시하고 나머지 검증용 계정 121개는 사용 불가로 유지했다.

별도 ETL 저장소가 없는 임시 소스 사본에서 B 계약 381개, 게시 계약 13개, 인프라 표현식 검사 9개, **총 403개의 오프라인 검사가 통과했고 skip은 0개였다.** 검증된 Python 소스 세 개를 바이트 그대로 fixture로 고정하고 실제 Java BCrypt 검사도 수행했다. JAR 누락과 fixture 변조가 실패로 처리되는 것도 확인했다. [재현 명령과 fixture 출처](../../infra/aws/tests/fixtures/etl-account-runtime/README.md)를 함께 제공한다. 원격 PR CI는 이 요약 작성 시점에 아직 실행하지 않았다.

Mac과 VM 여유를 더하지 않는다. Docker.raw는 MySQL·Elasticsearch를 포함하므로 사용량도 중복 합산하지 않는다. MySQL metadata의 DATA 32.878GB·INDEX 18.693GB는 ANALYZE를 새로 실행하지 않은 추정치이며 별도 물리 사용량이 아니다. 동일 덤프의 hardlink 4개도 네 배 공간이 아니다. 인수 구간의 표본 551개 중 실패·부분 관측 53개와 최대 576.054초의 관측 간격을 보존했다. 표본의 최소 여유나 최대 사용량을 전체 생성 과정의 순간 최고 사용량으로 주장하지 않는다.

검증 한계도 남아 있다.

- 한국 자정을 가로지르는 재고 검증 범위 문제는 코드로 수정하지 않았다. 같은 봉인 앱·도구로 자정 이후 두 번째 검증을 다시 시작해 통과했다.
- CDC 검사는 직접 삽입한 outbox 한 건의 전달 검증이다. 새 업무 API 쓰기 시나리오나 지속 부하 성능의 증거는 아니다.
- 실제 앱 실행은 `bootRun`으로 확인했다. IntelliJ 설정은 준비했지만 IDE 실행 버튼 동작은 검증하지 않았다.
- OCI·AWS 배포와 원격 복원은 검증하지 않았다. 인프라의 오프라인 검사 통과가 실제 클라우드 권한이나 배포 성공을 뜻하지 않는다. 외부 결제·S3 쓰기·Slack·Google API를 비활성화한 로컬 설정의 결과다.

원시 덤프, 봉인 실행 산출물, native snapshot, 비공개 계정 자료, 전체 로그와 성공·실패 영수증은 Git 밖의 영구 보관 대상으로 유지한다. 공개 JSON에는 데이터 규모·바이트 수·검증 상태·논리적 근거 이름과 SHA만 남겼다. 비밀번호, 개인 경로, 호스트 주소, 서버 식별자, 실행 세션은 공개 요약에 포함하지 않는다. SHA는 보존 원본의 동일성을 확인하는 값이며 원격에서 검증을 다시 수행했다는 뜻은 아니다.
