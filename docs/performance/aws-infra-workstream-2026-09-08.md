# AWS 데이터 승인·반복 실험 작업 결과

작업 브랜치: `codex/aws-lab-fresh-start`, 분기점 `94477de9`.
사용자가 별도 채팅에서 진행하는 ETL·데이터 생성과 분리한 작업이다.

## 구현 내용

- 호스트 권한 경계에 데이터 준비 기록 읽기 권한을 보완했다. 각 역할의 실행별 쓰기 범위는 유지하고, 스냅샷 복원 호스트에는 승인 원본 기록 한 개만 추가로 읽게 했다.
- foundation의 private DNS 관리가 실험 VPC 연결을 지우지 않도록 했다.
- monitoring 보안 그룹에서 앱 호스트 지표의 TCP 9100 접근을 허용했다.
- 새 AWS lab은 정확한 MySQL 8.4 패치와 `mysql8.4` 파라미터 그룹을 사용하고 확장 지원을 비활성화한다. 생성 전 서울 리전에서 해당 패치가 제공되는지 확인한다.
- AWS용 Debezium은 3.5.2.Final과 다운로드 SHA-256을 고정했다. OCI는 기존 Dockerfile의 2.6.1.Final 선택을 유지한다. AWS 커넥터·내부 토픽 이름을 현재 outbox 규약에 맞추고 MySQL 연결에 TLS를 요구한다.
- `aws-lab.sh prepare` / `make aws-prepare`를 추가했다. DB와 검색 데이터를 전체 검증한 뒤 승인용 기록을 남기고 끝낸다. ALB·앱 ASG·앱 기동 문서는 만들지 않으며, 쿠폰 등 실험 상태를 변경하기 전에 종료한다.
- `dataset-qualification.json`에는 원본 manifest 해시, 릴리스·생성 실행, MySQL 스키마·검증 지문, 검색 스냅샷 계약, 원본 RDS ID·엔진, 최초 전체 검증 결과를 기록한다. S3 객체 버전과 내용 해시를 스냅샷에 연결한다.
- 스냅샷 승격은 준비 기록만 사용한다. 앱 이미지·캐시·ASG 설정과 direct-readiness는 승인 조건이 아니다. 앱 ASG가 있는 실행은 기준 스냅샷 승격을 거부한다.
- 반복 복원은 승인 기록·엔진·Flyway·스키마·소수 PK 조회·검색 count/mapping/alias·Redis·Kafka·CDC를 확인한다. 전체 테이블 COUNT, 전체 행 지문, 관계·집계 검사와 ES 전체 scroll은 다시 실행하지 않는다.
- 실행 완료 기록은 schema 3이며, 데이터 지문을 최초 검증에서 승계한 경우 `verification.mode=approved-snapshot`과 원본 기록의 버전·내용 해시를 명시한다. 앱 이미지와 실험 설정은 해당 실행의 direct-readiness 기록에 남긴다.
- 준비 단계의 이름·종료 상태·소요 시간을 기록한다. 승인 출처와 MySQL 버전 오류는 리소스 생성 전에 확인한다. 기존 실행 잠금·실패 정리·TTL 정리는 준비 작업에서도 공유한다.

## 검증과 한계

작은 격리 Docker 환경에서 실제 MySQL 8.4.8 → Debezium 3.5.2.Final → Kafka를 실행했다. 커밋 이벤트 전달, 롤백 이벤트 제외, 커넥터 재시작 중 발생한 이벤트 복구가 통과했다. 전달 보장은 at-least-once이며 중복 가능성을 제거했다고 주장하지 않는다. 테스트용 컨테이너·네트워크·DB 볼륨은 종료 시 정리했다.

Terraform 모의 검증은 foundation 39개, lab 53개가 통과했다. 준비 작업의 ALB·ASG 미생성, DNS 관리, 권한 경계, 지표 접근, 엔진 계약을 포함한다. 별도의 실행 테스트는 승인 기록 변조·버전 교체 거부, 중복 승격 요청의 일관성, 앱 설정과 무관한 재사용, 전체 DB/ES 검사 생략과 누락된 샘플 거부를 확인한다.

실제 AWS 자원 생성·삭제, 이미지 게시, 데이터 업로드와 스냅샷 승격은 수행하지 않았다. 준비 시간·RDS lazy loading·워밍업·실제 비용은 AWS 통합 실행 후 측정한다. 6시간 TTL은 최대 보유 여유이며 실험이 끝나면 바로 `down`할 수 있다. 승인 스냅샷·S3 보관 비용은 별도로 남는다.

## 새 ETL 산출물이 오면 연결할 부분

현재 소비자 어댑터는 기존 V27 / benchmark-dataset-v2 명세, 고정 규모·검증 목록을 유지한다. 새 한국 데이터 전체 구성이나 변경된 실험 목록을 이 명세로 억지로 승인하지 않는다. 다른 채팅에서 작은 manifest 샘플과 마이그레이션 목록이 나오면 어댑터·실험 대상·쓰기 상태 준비를 맞춘다.

필요한 전달물은 ETL 커밋, 정확한 MySQL 버전, manifest와 파일 해시, 마이그레이션 이력, 검증 결과, 산출물 경로다. 전체 생성 전에 작은 샘플로 import·최초 검증·스냅샷 복원을 확인한다. 승인 후에도 쓰기 실험의 변경 결과와 실험별 불변식은 매번 검증한다.

실행 예시는 [데이터 승인과 반복 복원](aws-dataset-approval-and-reuse.md)을 따른다.
