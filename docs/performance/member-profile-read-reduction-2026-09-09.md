# 내 회원정보 조회 개선

## 판단과 프론트 소비 근거

대상은 `GET /api/v1/auth/me`다. 프론트 작업트리 `codex/editable-booking-review`에서
원격 main을 다시 가져왔고, `origin/main`의 `f80bc095`는 이미 작업트리에 포함되어 있었다.

| 응답 필드 | 실제 소비 | 판단 |
| --- | --- | --- |
| `id` | `sessionState.ts`의 `toSessionSubject`가 회원 식별자를 생성한다. 회원 전환 시 캐시와 세션 소유 범위를 구분한다. | 유지 |
| `email` | `ReservationConfirmRoute.tsx`가 결제 고객 이메일로 전달한다. | 유지 |
| `nickname` | `ReservationConfirmRoute.tsx`가 결제 고객 이름으로 전달한다. | 유지 |
| `thumbnail_image_url` | 본인 회원정보의 wire 타입·mapper·모델과 테스트 fixture에만 있었고 화면에서는 읽지 않았다. | `/auth/me` 응답과 `AuthViewer`에서 제거 |

후기 작성자·숙소 호스트·예약 게스트를 표시하는 다른 회원 DTO의 이미지 필드는 사용 중이므로 유지한다.
회원 엔티티, 회원가입 입력, DB에 저장된 프로필 이미지도 유지한다.

이 조회는 회원 한 행에서 필요한 세 값을 함께 읽으면 된다. 쿼리를 나눌 이유가 없으며,
전체 엔티티 조회를 `MemberProfileProjection(id, email, nickname)`으로 바꿨다.
역할·비밀번호가 필요한 로그인이나 세션 발급의 잠금 조회와 합치지 않는다.
각 경로의 필요한 데이터와 트랜잭션 목적이 다르기 때문이다.

## 보존한 동작

- 조회 ID는 요청 파라미터가 아닌 `@CurrentMemberId`로 전달된다.
  세션 인증 필터와 `UserContext`를 통한 현재 회원 식별을 유지한다.
- `id = memberId AND status = ACTIVE` 조건을 유지한다.
  활성 MEMBER·ADMIN 모두 조회할 수 있고, 탈퇴·휴면·미존재 회원은 기존 `M001` 오류를 반환한다.
- 로그인 비밀번호 검사, 세션 발급의 회원 잠금, 회원 탈퇴 이력 및 세션 무효화,
  관리자 권한 확인 경로는 변경하지 않는다.
- 별도 프로필 캐시를 도입하지 않는다. 이후 조회는 DB의 변경된 이메일·닉네임을 반환한다.

응답의 `data`는 다음 세 필드다. 백엔드 직렬화 테스트와 프론트 API mapper 테스트는
내용이 같은 `auth-me-profile.json` fixture를 사용한다.

```json
{
  "id": 41,
  "email": "profile@test.invalid",
  "nickname": "예약 회원"
}
```

프론트 mapper는 이전 응답에 이미지 필드가 추가로 있어도 세 값만 추출한다.
기존 이미지 표시 기능을 제거하는 UI 변경은 없다.

## 측정

MySQL 8.4.11 Testcontainers에서 직전 구현 `735e8386`과 같은 회원 데이터를 사용했다.
서비스 호출 전에 영속성 컨텍스트와 Hibernate 통계를 초기화했다.

| 항목 | 이전 | 이후 |
| --- | ---: | ---: |
| 서비스 호출당 SQL 수 | 1 | 1 |
| SELECT 컬럼 수 | 11 | 3 |
| 활성 회원 조회 시 엔티티 적재 | 1 | 0 |
| 다른 테이블 조인 | 0 | 0 |

변경 후 SELECT에는 비밀번호·역할·상태·이미지·감사 필드를 포함하지 않는다.
상태는 WHERE 조건으로 계속 검사한다. 이 측정에는 HTTP 인증 필터의 Redis 접근을 포함하지 않는다.
운영 지연 시간이나 처리량 개선 비율은 측정하지 않았다.

## 검증

- 백엔드 39개 통과: 실제 MySQL 회원 조회 6개와 회원 서비스·인증 컨트롤러·로그인·
  세션 발급·인증 필터·현재 회원 resolver·세션 저장소·관리자 인가 테스트 33개.
- MySQL 테스트에서 활성 회원의 두 역할, 탈퇴·휴면·미존재 회원, 다른 회원으로의 조회 대체 방지,
  이메일·닉네임 갱신 반영, 저장된 비밀번호·이미지 보존을 검증했다.
  각 측정은 SQL 1회·SELECT 3컬럼·엔티티 적재 0개를 확인한다.
- 프론트 인증·세션·provider·라우트 관련 479개 통과.
  본인 회원정보 fixture에서만 이미지 필드를 제거하고 다른 회원의 이미지 fixture는 유지했다.
- 브라우저 6개 통과: 로그인 후 보호 URL 복원, 로그인 전 위시리스트 의도 취소·재개,
  탭 간 로그아웃·다른 회원 로그인 전파, 로그아웃 실패 시 로컬/다른 탭의 세션 처리.
- 제품 코드와 브라우저 테스트의 타입 검사, strict lint와 E2E lint 통과.

세션 저장소 검증은 기존 단위 테스트이며 실제 Redis 통합 테스트를 실행한 것은 아니다.
브라우저 검증도 응답 fixture를 사용하며 실행 중인 백엔드와 연결한 E2E는 아니다.
인덱스·DB 스키마·ES 검색은 변경하지 않았다. 다른 조회에 대한 검토와 실행계획·지연 시간 측정은 별도다.
