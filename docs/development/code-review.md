# AI 코드 리뷰 기준

airbob의 변경은 대부분 AI 코딩 에이전트(Claude Code)가 작성한다. 이 기준은 그 변경을 리뷰하는 다른 AI(Codex, Claude)가 따른다.
리뷰 방식과 판정 기록은 [AI 리뷰 기록](ai-review-log.md)에 있다.

## 무엇을 보나

작성자가 놓친 결함을 찾는다. 프로젝트 규칙은 `CLAUDE.md`와, 바뀐 파일에 해당하는 `.claude/rules/*.md`에 있다. 변경이 그 불변식을 어기는지도 확인한다.

## 지적하기 전에

- 코드를 직접 읽어 확인한다. 가능하면 테스트나 입력으로 재현한다.
- 확인하지 못했으면 "확실하지 않음"이라고 쓴다.

## 지적하지 않는 것

- CI가 이미 강제하는 것: 컴파일, 테스트 통과, ArchUnit, OpenAPI 스냅샷, `scripts/ci/contracts.py`, GitHub Action의 SHA 고정
- 비현실적인 전제가 있어야 일어나는 경로
  - 외부 API가 계약과 다른 응답을 보내는 경우(예: 정수 필드에 `null`)
  - 러너나 플랫폼의 비정상 동작(예: 러너가 제공한 파일에 쓰지 못함)
  - 프로세스가 특정 순간에 강제 종료되는 경우
  - 이 저장소의 변경에서 나올 리 없는 극단적인 입력
- AI 리뷰 기록: `docs/development/ai-review-log.md`의 "기록" 표와 PR 본문의 "AI 리뷰" 절. 작성자가 판정을 정리한 결과이고, 그 집계와 형식은 작성자가 책임진다.

이 목록은 같은 이유로 넘기거나 오탐으로 판정한 지적이 반복될 때 늘린다.

## 심각도

| 심각도 | 뜻 |
|---|---|
| 필수 | 버그, 보안 문제, 데이터 손상, 계약(API·DB·잠금 순서) 위반 |
| 권장 | 경계 조건, 바뀐 동작의 테스트 누락, 문서·규칙 불일치 |
| 참고 | 작성자의 판단에 맡기는 의견 |

## 출력

한국어로 쓰고, 아래 틀을 그대로 따른다. 제목 단계, 항목 이름, 굵게 쓰는 위치도 바꾸지 않는다.

~~~markdown
## 요약
필수 N건, 권장 N건, 참고 N건. 총평 한두 문장.

## 지적

### 1. [권장] 한 줄 제목
- **위치:** `scripts/ci/claude_review.py:42`
- **문제:** …
- **근거:** 확인하거나 재현한 방법. 확인하지 못했으면 "확실하지 않음"이라고 쓴다.
- **제안:** …

## 확인한 범위
- …

## 확인하지 못한 것
- …
~~~

- 지적은 필수, 권장, 참고 순서로 번호를 매긴다. 지적이 없으면 "## 지적" 아래에 "지적 없음"이라고 쓴다.
- 위치는 저장소 기준 상대 경로와 줄 번호로 쓰고, 링크로 만들지 않는다. 여러 곳이면 쉼표로 잇는다.
- 확인하지 못한 것이 없으면 "없음"이라고 쓴다.
- 틀 밖의 머리말, 맺음말, HTML 주석은 쓰지 않는다.
