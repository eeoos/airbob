# PR 제목과 본문

형식의 원본은 `.github/pull_request_template.md`다. 웹에서 PR을 만들면 GitHub이 이 파일로 본문을 채운다. 하지만 `gh pr create`에 본문을 넘기면 이 파일은 쓰이지 않으므로, 이 스킬로 같은 형식을 맞춘다.

## 제목

- 커밋 메시지처럼 `<type>: <무엇을 하는지 한 문장>`으로 쓴다. 예: `chore: 네이버 컨벤션 포매팅을 Spotless로 강제한다`
- 제목만 읽어도 무엇이 바뀌는지 알 수 있어야 한다. "버그 수정" 같은 제목은 쓰지 않는다.

## 본문

템플릿의 절 순서를 따르고 안내 주석(`<!-- -->`)은 지운다. 한국어로 쓴다.

- **요약:** 무엇을, 왜. 해결할 문제를 한두 문장으로 쓴다. 여러 PR로 나눈 작업이면 전체 중 어디인지도 적는다.
- **변경:** 어떻게. 설계 결정, 고른 이유, 버린 대안을 쓴다. diff로 보이는 파일 나열은 줄이고 묶음별로 쓴다.
- **검증:** 실행한 테스트·명령과 결과(개수, 수치), 재현 방법을 쓴다. 확인하지 못한 것과 그 위험도 쓴다.
- **주의 사항(선택):** 머지하는 사람이 판단하거나 알아야 할 것을 모은다. 위험, 머지 방식(예: 머지 커밋으로 합쳐야 함), 머지 뒤 할 일(순서대로), 알려진 한계와 후속 작업. 없으면 절을 뺀다.
- **AI 리뷰:** `pr-ai-review` 스킬 A.5의 형식을 따른다. 문서만 바뀌어 리뷰를 건너뛰었으면(A.1) "문서만 바뀌어 생략"이라고 쓴다.

그 밖의 규칙:
- 본문에 Claude 표시("Generated with Claude Code", Co-Authored-By)를 넣지 않는다.
- 리뷰나 수정으로 설계가 바뀌면 머지 전에 본문을 바뀐 내용에 맞춘다. 본문은 머지 뒤에도 남는 변경 기록이다.

## 명령

`gh`는 Claude 샌드박스 밖에서 실행한다. 샌드박스 안에서는 TLS 오류가 난다.

- 본문은 스크래치패드 파일에 써서 넘긴다. 대상 브랜치는 보통 `main`이고, 머지되지 않은 이전 PR 브랜치 위에 쌓았으면 그 브랜치다.
  ```
  gh pr create --base <대상 브랜치> --title "<제목>" --body-file <파일>
  ```
- 본문을 고칠 때는 `gh api -X PATCH repos/eeoos/airbob/pulls/<번호> -F body=@<파일>`을 쓴다. `gh pr edit`은 classic Projects 조회 오류로 실패할 수 있다.
- PR을 만들 때 `claude-review` 라벨을 붙이지 않는다(`pr-ai-review` B.1).
